# Advisor v0.2.7

发布日期：2026-10-31
上一版：`v0.2.6`（`cbaf8a5`，2026-10-31）
本版范围：`v0.2.6..v0.2.7`，5 个提交（+ 本版说明这 1 个 = 6）

## 一句话

**这一版全在补「回复送不到你手上」**：回一句 `1` 就被 DeepSeek 422、早上 8 点它以为还是昨晚
23:19、跑完一次重启就彻底失联。根因有三个层次——JSON 里数字样子的字符串被编成数字、
系统提示没有当前时间、以及回复只有一条出口且绑死在入站消息的 `req_id` 上。
现在：数字仍是字符串、每轮带准确时间、**所有出站文本先落盘再发**，重启/崩溃不丢内容。

## 模型侧

### 回一句 `1` → HTTP 422（`0df7411`）

`messages[641]: content should be a string or a list`。根因是 `MiniJSON::encode` 按
「看起来像数字」判断类型：用户输入的 `"1"` 被编成 JSON 数字 `1`，OpenAI 容忍、**DeepSeek
（Rust serde）直接 422**。上一版修的是 `content:null`，这次是数字，同一句话的另一个成因。

- 改按 Perl 标志位判类型：`SVp_IOK`/`SVp_NOK` 且没有 `SVp_POK` 才算数字，`"1"`/`"007"` 仍是字符串
- 出口兜底扩到数字；`tool` 消息的 content 同样处理
- 诊断并入错误正文（原来单独发一条 note 会被漏看），数字标成 `number(1)`

### 早上 8 点却以为 23:19（`0df7411`）

系统提示里没有「现在几点」，而常驻会话（远程 / `--continue`）的历史带着昨晚的工具输出，
模型把旧时间戳当成现在，于是按安静时段把你的请求拒了。现在 `system_prompt()` **每轮**
追加一行权威时间（本地时间 + 星期），并写明「此前的时间戳只是历史」。

## 远程：回复不能再无声丢掉

### 出站队列（`83bafc0`）

`aibot_respond_msg` 必须带入站消息的 `req_id`，它只存在于正在跑的进程里 —— 服务一重启，
这一轮的回复就没有接收方。现在**先落盘再发、发成功才删**：

- `~/.claude-agent/outbox/<发送者>.txt`（0600 / 目录 0700），一行一条
- 没发成功的留着：这个人下次发消息时先带「（下面是重启前没能送达的回复）」再给新回复
- 配了 webhook 就在启动时**主动推**一次

### 被打断的那一轮（`32ccc7c`）

命令把宿主杀掉时这一轮**根本没产生回复**，队列里没东西可补（所以审计里连
`outbox_undelivered` 都没有——空队列不记日志）。现在进消息时落
`~/.claude-agent/inflight/<发送者>` 标记、回复发成功才删；重启后见残留就补一句
「上一轮在重启/崩溃前被打断了，没有产生结果，当时你让我做的是：「…」」。

### 重启前先给回执（`32ccc7c`、`596a2d4`）

`run_shell` 执行前识别「会重启自己」的命令并先说一句。真机踩过两个坑，都已修：

- `\brestart\b` 漏掉 `restart_remote.sh`（下划线也算单词字符）→ 改成
  `(?<![a-z0-9])(?:kill|pkill|…|reload)`；`kill <pid>` 也会与本进程/父进程/pid 文件比对
- 同一轮连发两句 ⚠ → 同一条命令只提示一次

### 过程话也要落盘（`b5cf04c`）

只存最终回复时，重启会把「⚠ 这条命令会重启远程服务…」这句过程话正好吞掉——既没送达、
也没进队列。现在所有出站文本都落盘，只有最终回复发成功才清空；「正在处理，请稍等…」
这类纯占位不进队列。

### 幽灵进程（`596a2d4`）

真机定位到：主服务外多了一个子进程，没有网络连接、卡了一个多小时、命令行仍是
`wecom-ws.pl`。根因是 `open(my $ph, '|-')` 的经典陷阱——子进程里返回值是 `0`，
而 `if (!$pid)` 把它当成「fork 失败」直接 `next`，**`exec` 永远没执行**，子进程接着跑
父进程的代码并继承了 WS 套接字。现在判断改 `if (!defined $pid)`，失败才
`POSIX::_exit(127)`；并且**没有配 webhook 就根本不 fork**。

### 主动补发判错了文件（本版最后一块）

上一版按 `-f notify.conf` 判断能否主动推 —— 但 `notify.pl` 读的是
`~/.claude-agent/remote.conf` 里的 `WECOM_WEBHOOK` / `FEISHU_WEBHOOK`，
**没有 `notify.conf` 这个文件**，所以那条路在真机上永远不可能走通。已改成按
`remote.conf` 里真有 webhook 键才 fork，并第一次给这条链路补了端到端卡口。

## 升级

```bash
cd ~/advisor && git pull
./setup.sh            # 用 setup.sh 装过独立副本（~/claude-build/）的必须重跑
```

然后在 GUI 里**先停远程服务、再启动**（常驻进程用旧代码，不重启不生效）。

想让「重启完成主动收到一条」真的成立，在 `~/.claude-agent/remote.conf` 加：

```
WECOM_WEBHOOK = https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...
```

并用 `perl remote/notify.pl --test` 验连通。**不配也能用**，只是补发要等你下次发消息。

## 已知限制

- **长连接不能主动发起**：没有 `req_id` 就发不出去，这是协议层限制。要「重启后立刻主动收到」
  必须配 webhook（自建应用）。「自己伪造一条请求/编一个 `req_id`」在协议上不成立。
- Apple Developer ID 仍未配置：产物未签名，首次打开需右键 → 打开。
- `v0.2.5` 之前的 Gitee 同步 403 根因仍未闭环（`ADVISOR_MIRROR_DEBUG=1` 可抓，尚未复现）。

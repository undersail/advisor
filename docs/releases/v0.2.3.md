# Advisor v0.2.3

发布日期：2026-10-28
基线：上游 `watermark-hd/advisor` @ `7ab0b24`（2026-09-21）
上一版：`v0.2.2`（`adf97ff`，装完真能用 + 中继换 Durable Object）
本版范围：`v0.2.2..v0.2.3`

## 一句话

给「AI 能动手」这件事装上**可解释的闸门**：交互模式三档 + 可写范围 + 审计日志，
并把密钥这件事彻底收口成**两个入口**（安装时，或专门命令 `/key`）——
顺手修掉四个只有真机才会暴露的 bug：GUI 打不了字、GUI 存不了密钥、
`setup.sh` 用错模型名却怪你的 key、远程聊天端能改配置。

## 新增：交互模式三档（`default` / `accept-edits` / `bypass`）

| 模式 | 写文件 | 跑命令 | 危险命令 |
|---|---|---|---|
| `default` | 每次确认 | 每次确认 | **确认** |
| `accept-edits` | 自动 | 每次确认 | **确认** |
| `bypass` | 自动 | 自动 | **仍要确认** |

- 切换：`--mode=…` / `CLAUDE_MODE` / 会话内 `/mode` / GUI 页眉「模式 ▾」+ 常驻徽标
- 可写范围是**会话级多目录**：`--allow-write` / `CLAUDE_ALLOW_WRITE` / `/allow-write <dir>`；
  `~/.ssh`、`~/.claude-agent`、`/etc`、`/usr` **即使显式加入也拒绝**
- 危险命令的确认是 **fail-closed**：60 秒无人回答即拒绝；无终端又无 GUI 时直接拒绝
- 每次自动批准都写一行 `~/.claude-agent/approvals.log`（0600，只追加），`/approvals` 可回看

## 新增：`/key` —— 密钥的唯一会话内入口

- `KEY` 只在两处输入：**安装流程**（`setup.sh`）或 **`/key <厂商>`**
- `/key` 列出 7 家的配置状态；`/key anthropic` 隐藏输入 → 保存到 `~/.claude-agent-env`（0600）
- 切换模型（`/model`、`/claude` `/deepseek`…）**不再问密钥**：缺密钥只提示
  「用 `/key <厂商>` 配」，并且仍停在原模型
- 密钥被拒（HTTP 401/403）单独识别成「密钥被拒绝」，指出该查哪个变量并让你退出后重配，
  不再把原始 JSON 甩到屏幕上

## 安全：远程只对话

远程（企业微信 / 飞书）进来的消息现在带 `--no-config`：厂商、模型、模式、可写范围、密钥
**一律只能在本机配置**，聊天端发 `/model` `/mode` `/allow-write` `/key` 会被直接拒绝并回一句
说明；审计记 `session_start … no_config=1`。理由有两条：远程改配置会让本机行为莫名变化；
**密钥绝不该经第三方聊天平台转一圈**。

远程依旧只有两个只读工具（`read_file` / `list_dir`），删掉 `remote/` 本地行为一字不变
（`check-decoupling.py` 守着，含「网关必须真的传下去」的断言）。

## 修掉的真 bug（都只有真机才暴露）

### 1. GUI 打开了，但对话界面打不了字

整个 GUI 里**没有任何一处**给写作框 `focus_set()` —— 窗口一开，焦点不属于任何控件，
按键直接丢弃。从 Finder 双击启动最明显（从终端起有时会落到第一个控件上，所以一直没发现）。
现在启动时 / 后端 `ready` 后 / 每轮忙完 / 窗口重新获得焦点时都会把焦点交给写作框。

### 2. 后端退出时 GUI 静默变石头

进程 EOF 后只把输入框 DISABLE、状态栏留一句「已退出」，**没有任何原因**，而 stderr 被
`subprocess.DEVNULL` 丢掉。现在 stderr 保留最后 20 行，退出时在对话区打出
「后端进程已退出」+ 错误原文 + 处理办法（关掉重开，或终端跑 `advisor` 看同样的错误）。

### 3. GUI 报「配置文件没权限」，而命令行 `setup.sh` 却能写

GUI 用 `open(path,'w')`（需要**文件本身**可写），setup 用 `mv`（只要**目录**可写）。
所以 `~/.claude-agent-env` 只要是 sudo 建的或只读，就出现「命令行能写、GUI 写不进」。
现在统一为同目录临时文件 + `os.replace`；真写不进时报「路径 / 属主 / 权限 / `sudo rm` 再试」。

### 4. `setup.sh` 用错模型名，却提示「密钥不正确」

连通性检查沿用了 `~/.claude-agent-env` 里**上一家厂商**的 `CLAUDE_MODEL`。真机实测：
拿 anthropic 的 `claude-opus-5` 去请求 DeepSeek → `400 The supported API model names are
deepseek-flash, deepseek-v4-pro, but you passed claude-opus-5`，而文案写的是「请确认密钥是否正确」。
现在：模型名必须属于所选厂商，否则回落到该厂商默认并告诉你；同时把 `CLAUDE_MODEL` 写回配置，
**厂商与模型不会再漂移**。HTTP 400 且报文提到 model 时会额外提示去查 `models.txt`。

### 5. `models.txt` 里 DeepSeek 的模型名本来就是过期的

服务端只认 `deepseek-flash` / `deepseek-v4-pro`，我们写的是 `deepseek-chat` / `deepseek-reasoner`。
已按服务端返回的名单更新，默认模型 = `deepseek-flash`。

### 6. 恢复会话后会再弹一次厂商菜单

启动横幅无条件弹厂商列表，`--resume` 选完会话紧接着又弹一次编号列表 —— 很容易被当成
「继续选会话」而误按。现在 `--resume` 之后只打一行 `[厂商 / 模型]` 和「要换 AI 请输入 `/model`」。

## 升级

```bash
cd <你的 advisor 目录>
git pull
bash setup.sh          # 会把新的 claude-agent.pl / advisor_gui.py / models.txt 放进 ~/claude-build
```

装完直接双击 `Advisor.app` 即可；命令行用户 `advisor` 一行。

# Advisor v0.2.4

## 一句话

**手机派活这件事，从「理论上支持」变成「真机真能用」**：企业微信智能机器人长连接（只要
BotID + Secret，不用公网域名、不用云账号）、权限在 Mac 上启动时定档、需要确认的操作发到手机
上回 y/n、单实例保护与优雅退出、GUI 里点两下就能配。附带价值是**真机暴露的六个 bug 全部修掉**，
其中五个是「本地测试全绿、真机一用就废」的类型 —— 这才是本版最有分量的部分。

## 新增：企业微信长连接（不用公网、不用云账号）

- `remote/wecom-ws.pl`：`--init` 配凭据、`--check` 自检、`--serve` 常驻
- 协议：`aibot_subscribe`（BotID + Secret）→ `aibot_msg_callback` → `aibot_respond_msg`
- 心跳 30 秒、退避 1→30 秒、`SIGPIPE` 忽略、EOF 当断线重连（不空转烧 CPU）
- 只依赖 perl 自带模块 + `openssl s_client`：**零 CPAN**（XS 要 Xcode CLT，模块还绑死某个 perl 的 `@INC`）
- 原来那条 Cloudflare Worker 中继方案**整段删除**（`ddc8319`）：长连接已覆盖同一需求，
  而中继要求用户自己开云账号、部署 Worker、`secret put`，与「双击即用」冲突

## 新增：远程权限改成「启动时定档 + 手机确认」

旧口径（远程一律只读、代码里硬关 `write_file`/`run_shell`）作废。现在：

| 档位 | 工具集 | 危险操作 |
|---|---|---|
| `default` | `read_file,list_dir` | — |
| `accept-edits` | 追加 `write_file,run_shell` | 手机确认 |
| `bypass` | 同上 | **仍要手机确认** |

- 档位**只在 Mac 上启动时指定**（`--mode=` / GUI 下拉），运行中手机端改不了
- 需要确认的操作转发到手机：`⚠ 危险操作，需要你在手机上确认…回复 y 允许 / n 拒绝`；
  不回则超时按**拒绝**（fail-closed，默认 120 秒）
- 工具集由 `effective_tools()` 单点决定、档位解析由 `writable_mode()` / `effective_mode()` 单点决定
  —— 防「两处各判一次」的漂移；`check-decoupling.py` 机器卡口盯着

## 新增：单实例保护 + 优雅退出 + GUI 启停

- `~/.claude-agent/wecom-ws.pid` 上加 `flock`：第二个实例 **exit 3** 并告诉你已有实例的 pid 与档位
  （两个实例会各起一个 agent，同一条消息被处理两遍 —— 回复重复、文件和命令被执行两次）
- pid 内容 `pid / mode / allow_write / started / version`（**不含密钥**，0600）
- `INT`/`TERM`/`HUP` → 审计 `ws_stop`、清 pid、放锁、exit 0
- GUI「工具 → 远程接入…」：BotID / Secret（掩码、保存后清空）/ 白名单 / 远程权限 / 可写目录 /
  保存 / 测试连接 / **启动服务** / **停止服务** + 状态行（读 pid 判活，`kill -9` 残留不误报）
- 同一份配置、同一个 pid 文件、同一个服务 —— 命令行与 GUI 只是两个入口

## 修掉的真 bug（六个，全部只有真机才暴露）

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 连 `wss://` 报「握手被拒」，明明后面跟着 `HTTP/1.1 101` | `openssl s_client` 即使带 `-quiet` 也把证书校验信息写到 stdout，HTTP 头不在缓冲区开头，`^HTTP/1.1` 匹配失败 | 先剥噪声再判 101；证书包按 `SSL_CERT_FILE` → 缓存 → 平台常见路径 → **macOS 从钥匙串导出**；`-CAfile` + `-verify_return_error` fail-closed；证书错 **exit 5**，不再每 30 秒重试 |
| 2 | 证书校验失败只剩一句「握手时连接被关闭」，读不到原因 | `open3($in,$out,$errh,…)` 的 `$errh` 是 undef（漏了 `gensym`），子进程 stderr 根本没接进管道 | `gensym` + 有界读取 + 诊断 |
| 3 | 手机发消息完全没反应，日志只有 `session_not_ready` | 起 agent 失败时把子进程 stderr 丢掉，且回空串 | 透出 stderr（UTF-8 解码）+ 手机回一句话 |
| 4 | 报「请设置 ANTHROPIC_API_KEY」，但配的是 DeepSeek | ①env 解析只认 `export NAME=value`（等号两边不许有空格），②读不到文件时静默返回空 | 宽容解析（export 可有可无 / 空格 / 引号 / 注释 / CRLF）；「读不到」与「没有」分开报并给 `chown`+`chmod` 修法；启动时 `config_sanity()` 自检 |
| 5 | 消息发出去被拒：`errcode=40008 invalid message type` | `aibot_respond_msg` 的 `msgtype` 只认 `stream`，`text` 只对欢迎语合法 | 回复改 `stream`（`id` 取回调 `msgid`、单条 `finish:true`、「正在处理…」用 `finish:false` 后被顶掉）；**假服务端现在照真服务端校验 msgtype** |
| 6 | 手机发中文，AI 说「你的消息显示成了乱码，意思能理解」 | `gateway.pl` 的 `STDOUT`/子进程管道有 `:encoding(UTF-8)`，**唯独 `STDIN` 没有** → 双重编码（`ä½ å¥½`） | 补 `binmode STDIN`；argv 文本显式解码；`json_unescape()` 改单趟扫描并支持 `\uXXXX`（含代理对） |

保活/重连另外按官方 SDK（`WecomTeam/aibot-node-sdk` 的 `src/ws.ts`）复核了一遍，对齐了三处：
**连通过一次后退避复位**（原来永久卡在 30 秒）、**订阅被拒阈值 3→5**、**补 `disconnected_event`**：
同一机器人在别处连上时服务端会踢本连接，现在**审计 `ws_kicked` + exit 4，不反复抢线**。

## 升级

```bash
cd <你的 advisor 目录>
git pull
bash setup.sh          # 会把新的 claude-agent.pl / advisor_gui.py / models.txt 放进 ~/claude-build
```

远程接入（如果要用）：GUI「工具 → 远程接入…」填 BotID / Secret / 白名单 / 权限档位，点「启动服务」；
或命令行 `perl remote/wecom-ws.pl --serve --mode=accept-edits`。

> **★ 不要用 `sudo` 跑 `setup.sh`、配置或服务。** `sudo` 会把 `~/.claude-agent*` 的属主变成 root，
> 之后普通用户就读不到了 —— 本版第 4 号 bug 的真机现场就是这么来的。
> 已经踩了的话：`sudo chown $(whoami) ~/.claude-agent-env && chmod 600 ~/.claude-agent-env`。

## 已知限制

- 需要 macOS 10.9+；Tier A（10.6~10.8）仅保留 `CLAUDE_CURL` / `CLAUDE_CACERT` 接口，未实现
- 分发包未签名，首次打开需右键 →「打开」（签名分发需 Apple Developer ID）
- 远程接入的**回调模式**（自建应用）仍需公网可达域名；长连接不需要
- 飞书长连接未实现（方案记在 `docs/design_doc_advisor.md` §4.5.2），飞书目前只有回调与出站通知
- 本版验证口径：自动化能覆盖到协议构造、逻辑分支、控件结构；**真密钥连通性、真实
  企微服务端行为、GUI 视觉排版、TLS 真机证书链**这几项仍只能在 macOS 真机上验
  （清单见 `docs/manual_test_mac.md`）

# Advisor v0.2.6

发布日期：2026-10-31
上一版：`v0.2.5`（`795ef09`，2026-10-31）
本版范围：`v0.2.5..v0.2.6`，13 个提交（+ 本版说明这 1 个 = 14）

## 一句话

**这一版几乎全是「手机上用不了」的真机缺陷**，不是观感问题：回了 `y` 却等来超时、任务跑完
却没有回复、从安装目录启动的远程服务根本起不来（agent 路径只认仓库布局）、本地维护命令被
API key 挡住、备份被 macOS 扩展属性判成失败。模型侧顺手修掉两类 422 的根因。确认时限与
Hermes 对齐，统一 **300 秒**。

## 远程：一条消息从进到出的三个缺口

### 1. 回了 `y` 却报「确认超时」（`36e08d0`、`d3eafc8`、`1a1f46c`）

主闸门本来就是闭合的（回 `n` 不执行、超时更不执行），但三个缺陷合起来能造出「还是执行了」
的观感：确认没有 id（迟到的答复被下一道题吃走）、旧客户端不带 cid 被当垃圾丢掉、
两侧等待不对称。现在：确认带 `cid`（`<pid>-<序号>`），**只认匹配的答复**；不带 cid 也照收
（兼容旧客户端）；超时立刻回「这次操作没有执行」；GUI 自制确认框（**回车=拒绝**、倒计时到点
自动撤窗）。

### 2. 答复比「等确认」更早到（`1fe4f34`）

手机的 `y` 在客户端还没记下「正在等确认」时就到了，旧实现把它当普通回合丢掉。现在收到的
纯 `y`/`n` 先攒在 `early_answer` 里（回一句「收到，正在等这一步的确认结果…」），真问到这一步
时直接用掉 —— 回复照常生效，但不给普通回合塞入不属于任何确认的答复。

### 3. 跑完了却没有回复（`9fefed8`）

手机上一条消息过去，电视都开始缓冲了，回复却是空的，审计只有 `reply_len=0`。根因：网关只认
`text`/`error`，`note` 一律忽略 —— 命令只走 note（如 `/history`）、模型只回了思考、工具链跑完
没写总结，三种走法都会得到空回复。现在 agent 每轮计数，一条正文都没有就补「这一轮跑了 N 次
工具调用，但没有产生总结文字」；网关侧再兜一层（`reply_empty_filled`）。

### 4. 确认时限统一 300 秒（`17ba188`）

原来本地 60、远程 120、网关 115 —— 都是拍出来的数。手机不在手上是常态，Hermes 的注释写得很
直白：`60s failed closed before Telegram taps landed`。现在本地/远程一律 **300 秒**，网关
**295**（永远早 5 秒收尾）。**手机侧终于有正门**：`~/.claude-agent/remote.conf` 里
`CONFIRM_SECS=600` 之类即可调，命令行 `--confirm-wait` 优先。超时照样按拒绝，且必须回执。

## 模型侧：两类 422 都是我们自己发错

### `content` 不能是 null（`1f6da20`）

长会话报 `422 … messages[430]: content should be a string or a list`。根因在
`build_request_openai`：纯工具调用那一轮的 assistant 消息没有正文，`content` 恒为 `undef`，
编码出来就是 `"content":null`。OpenAI 容忍，**DeepSeek（Rust serde）直接 422**。修两层：根因
处一律给字符串；出口再扫一遍（`--continue` 读回的旧会话里已经存了 null，只改根因治不了），
undef 与哈希对象都转成字符串并记下标。

### 422 被贴成「连不上模型服务」（`899deaf`）

上一版把所有失败都套「连不上」模板，连 401/422 也这么写，还印「试了 1 次」（重试次数被置 0
的副作用），中文模板四个占位只传了三个，② 后面空着。现在：**只有 HTTP 码为空/`000`** 才叫
连不上；业务错误原样透传厂商指认的消息；真不合规时回复里写「第 N 条消息：role=? content=?
带几个工具调用」。

### 报错不许原样怼给用户（`b6a9fef`）

从一段投屏交互记录里挖出四个问题：过程话占了回复位、同一参数错误连犯两次、拿 `206` 当
「播放成功」、连接失败无退避无交代。现在：连接类失败给出「厂商 · 地址 · 试了几次 + 三步排查」；
只对连接失败与 429/5xx 退避重试（2s、5s，最多 2 次，`CLAUDE_HTTP_RETRY` 可调）；
系统提示强制「哪里失败 + 为什么 + 下一个动作」，禁止说「重发」，同类失败连续 2 次必须停下汇报；
技能必须写绝对路径 + 参数格式 + 自检命令（远程 spawn 不走 shell，`~/bin` 未必在 PATH）。

## 远程服务怎么起来（三处同一个坑）

### 会话起不来，原因在你手机上看不见（`86a0486`）

原来只回「原因已写在 Mac 的终端输出和审计日志里」——人不在电脑前，等于没给原因。现在把子进程
stderr 开头直接拼进回复（长串凭据形态打成 `***`，截到 160 字），完整输出仍在审计里。

### GUI 起远程服务不传环境（`86a0486`）

命令行的 `~/bin/advisor` 和 GUI 自己的后端都 `export CLAUDE_CURL` / `CLAUDE_MODELS_FILE`，
但 GUI 起**远程服务**时 `Popen` 没给 `env` —— 只继承 GUI 进程的环境。从 Finder 双击启动的 GUI
没有 shell 里那些变量，于是两条启动路径看到的不是同一份环境。现在抽 `service_env()` 一体化。

### 从安装目录启动必然失败（`be69c90`，真机根因）

审计原文：`Can't open perl script "…/claude-build/agent/claude-agent.pl": No such file`。
网关把 agent 算成 `$SCRIPT_DIR/agent/claude-agent.pl`（**仓库**布局），而 `setup.sh` 装出来的是
**扁平**布局（`<build>/claude-agent.pl` + `<build>/remote/*.pl`）。所以从仓库跑一切正常，
从安装目录跑必然 `session_not_ready`。现在按候选顺序找：`CLAUDE_AGENT` → 仓库布局 → 扁平布局 →
`~/claude-build/`，全找不到就把**找过的每个位置**都写进审计；GUI 还会显式给出它自己用的那份；
网关启动即记 `agent_path=…`。

## 历史维护：两条路都别再挡人（`a43dd8f`）

- `--make-plain-history` / `--list-history` / `--change-passphrase` / `--set-recovery` 是纯本地
  操作，却在密钥检查之后才分发 —— 得先配个 API key 才能转明文。现在它们先分发、不校验密钥。
- 备份时 macOS `cp` 连扩展属性一起拷，普通用户对某些 xattr 没权限 → 逐文件 EPERM；旧实现
  「退出码非 0 = 备份失败」，内容明明都拷过去了还判失败。现在 `cp -R -X` 不拷扩展属性，
  且成败不看退出码，改成逐个核对「文件都在 + 大小一致」。
- 语义不变：**备份判失败就一个文件都不删**，宁可不转，也不丢历史。

## 升级

```bash
cd ~/advisor && git pull
```

用 `setup.sh` 装过独立副本的（`~/claude-build/`），要**重跑一次 `./setup.sh`** 才会同步 ——
`git pull` 不会更新那份副本。远程服务请**在 GUI 里先停再启动**，常驻进程用的是旧代码。

本版新增的排查抓手（都在 `~/.claude-agent/audit.log`）：

| 关键字 | 含义 |
|---|---|
| `agent_path=…` | 网关实际拉起的 agent 文件（新增，一眼看出用的哪份代码） |
| `session_not_ready … err=…` | 会话没起来，`err` 是子进程 stderr 开头 |
| `reply_empty_filled` | 本轮本来没正文，网关补了一句说明 |
| `early_answer` / `early_answer_used` | 答复比「等确认」更早到，已攒起来用掉 |
| `confirm_secs_conf` | 确认时限是从 `remote.conf` 的 `CONFIRM_SECS` 读的 |
